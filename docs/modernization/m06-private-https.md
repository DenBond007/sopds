# M06.5: внутренний HTTPS в локальной сети

Решение пользователя: Django и сканер работают нативно в Ubuntu 24.04,
Docker нужен только для тестовой БД. Собственного домена нет; доступ к SOPDS
нужен только из локальной сети. Выбран TLS на локальном Caddy с внутренним CA.
Это шаблон размещения, а не подтверждение работающего HTTPS. Текущий LAN-IP
или внутреннее имя сервера задаётся при запуске и может меняться между запусками.

## Настройки и запуск

- `SOPDS_PRIVATE_HOST`: текущий LAN-IP или внутреннее DNS-имя, которое
  читалка откроет по HTTPS, например `192.168.1.20` или `books.home.arpa`.
  Это одна адресная переменная для Django и Caddy. Для имени локальная DNS
  должна однозначно разрешать его в IP интерфейса Ubuntu также на самом
  сервере. Значения `0.0.0.0`, loopback и ошибочные IP отклоняются настройками
  Django. Адрес попадает в сертификат, `ALLOWED_HOSTS` и URL OPDS.
- `SOPDS_STATIC_ROOT`: отдельный абсолютный каталог только для результата
  `collectstatic`, доступный Caddy на чтение, например `/srv/sopds/static`.
  Исходные книги в этот каталог не помещать. Caddy под systemd обычно не
  сможет читать файлы внутри `/home`; каталог и права готовит оператор.
- `DJANGO_SETTINGS_MODULE=sopds.settings_private` задаёт `DEBUG=False`,
  HTTPS redirect, доверенный заголовок протокола от прокси и Secure cookies.
  Секретный ключ и реквизиты БД передаются теми же переменными, что и в
  базовых настройках; для размещения нужен отдельный секрет и своя БД.
- Gunicorn 26.2.0 добавлен в `uv.lock`. После подготовки окружения и БД
  оператор запускает его только на `127.0.0.1:8000` с
  `sopds.wsgi:application`; Django development server для размещения не нужен.
  Пример команды из корня проекта после загрузки переменных:

```bash
DJANGO_SETTINGS_MODULE=sopds.settings_private \
  .venv/bin/python manage.py collectstatic --noinput
DJANGO_SETTINGS_MODULE=sopds.settings_private \
  .venv/bin/gunicorn --bind 127.0.0.1:8000 sopds.wsgi:application
```

Сканер и worker аннотаций запускаются отдельно нативно. До запуска сканера
оператор явно проверяет, что `SOPDS_ROOT_LIB` указывает на предназначенную
для установки библиотеку; приложение не должно очищать каталог или полки.

`SOPDS_TEMP_DIR` в настройках Constance должен указывать на отдельный каталог
для конвертации, доступный пользователю Gunicorn на запись. Если его ещё нет,
приложение создаст его с правами `0700` при первом просмотре/конвертации;
для этого родительский каталог должен быть доступен на запись. Книги и static
в этом каталоге не хранить. Рабочие файлы каждого запроса удаляются после
конвертации. Значение по умолчанию — `tmp` в корне checkout.

Шаблон [Caddyfile.private.example](Caddyfile.private.example) берёт
`SOPDS_PRIVATE_HOST` и `SOPDS_STATIC_ROOT` из окружения процесса Caddy.
Он привязывает HTTPS к указанному LAN-IP или адресу, в который разрешается
внутреннее DNS-имя. `/static/` выдаётся из каталога `collectstatic`, остальные
запросы передаются Gunicorn на loopback. Caddy устанавливает `X-Forwarded-Proto` и по
умолчанию игнорирует пришедшее от клиента значение этого заголовка.
Нельзя открывать Gunicorn на сетевом интерфейсе или доверять иному прокси
без пересмотра `SECURE_PROXY_SSL_HEADER`.

При смене IP или DNS-имени обновите `SOPDS_PRIVATE_HOST` в окружении
Gunicorn и Caddy. Перезапустите оба сервиса с новым значением. Django
прочитает новый адрес для `ALLOWED_HOSTS` при старте; Caddy прочитает его
из шаблона и сам выпустит сертификат для нового имени/IP через `tls internal`.
Сравнивать адрес с
прошлым запуском в коде SOPDS и генерировать сертификат в Django не нужно.
Если DNS-имя осталось прежним, а изменился только его IP, переменную менять
не нужно. Перезапустите Caddy, чтобы он привязался к новому IP; сертификат
для того же имени можно продолжать использовать. Хранилище внутреннего CA
Caddy сохраняйте: при его потере устройствам потребуется доверить новый CA.
При смене адреса обновите ссылку в читалке; DNS-имя позволяет сохранить ссылку
при смене IP.

Внутренний CA Caddy нужно добавить в доверенные центры на устройстве с
читалкой. Оператор проверяет сертификат без обхода проверки TLS и права
доступа к порту 443 только из LAN. URL для читалки:
`https://<SOPDS_PRIVATE_HOST>/opds/`.

## Проверка перед использованием

1. На отдельной тестовой БД и копии искусственной библиотеки выполнить
   `manage.py check --deploy`, `makemigrations --check --dry-run`,
   `collectstatic --noinput`; проверить web, OPDS, скачивание и точные байты
   скачанной книги через HTTPS-прокси.
2. Проверить доступ из читалки без исключений сертификата: каталог, поиск,
   карточку, скачивание, обновление ленты с готовой аннотацией. Записать
   название, версию читалки и фактический результат в M06.4.
3. Проверить, что Caddy не слушает HTTP в LAN, Gunicorn доступен только с
   loopback, Secure-флаги cookie и static. Django перенаправляет случайный
   HTTP-запрос к локальному Gunicorn. После изменения адреса повторить
   проверку сертификата и читалки.

`SECURE_HSTS_SECONDS=0` оставлен намеренно. Предупреждение `security.W004`
из `check --deploy` допустимо до проверки HTTPS и доверия CA на реальном
устройстве; `W008`, `W012`, `W016` должны отсутствовать. HSTS рассматривать
отдельно только после успешной проверки выбранной схемы адресации. Пробный
пользовательский Caddy на порту 8443 и результаты HTTPS на искусственных
данных описаны в [m06-https-probe.md](m06-https-probe.md); порт 443 и
реальная читалка остаются непроверенными.

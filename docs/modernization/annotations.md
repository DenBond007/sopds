# Фоновые аннотации INPX

INPX scan импортирует только индексные метаданные. Он не открывает книги ради
аннотаций и не ставит всю библиотеку в очередь. При показе книги в web или
OPDS создаётся не более одного задания для её ID. Web и OPDS читают только
сохранённый `Book.annotation`; прежний служебный текст `NotYet` скрыт также
в Telegram-карточке. Открытая
страница web запрашивает состояние показанных книг раз в 5 секунд и обновляет
текст после завершения задания. OPDS увидит новый текст при следующем запросе.
Блок случайной книги не создаёт задания.

## Запуск и остановка в среде разработки

Сначала выполните миграции и настройте `SOPDS_ROOT_LIB` на
`$PWD/.local/library`, как указано в [README](../../README.md). В отдельном
терминале из корня checkout запустите один процесс:

```bash
set -e
set -a
. .local/dev.env
set +a
test "$DB_NAME" = sopds_dev && test "$DB_USER" = sopds_dev && \
  test "$DB_HOST" = 127.0.0.1 && test "$DB_PORT" = 5433
test "$(realpath .local/library)" = "$PWD/.local/library" && test ! -L .local/library
.venv/bin/python manage.py sopds_util getconf SOPDS_ROOT_LIB
.venv/bin/python manage.py sopds_annotation_worker
```

Проверьте вывод `getconf`: путь должен быть именно `$PWD/.local/library`.
Остановите worker через Ctrl+C или SIGTERM его процессу. Он завершит текущее
задание (не дольше 30 секунд извлечения), затем выйдет. Для одного прохода
доступен `sopds_annotation_worker --once`. После обычной или аварийной
остановки запустите ту же команду: незавершённое задание с истёкшим lease
будет взято снова через 60 секунд после предыдущего захвата. Токен lease
не даёт старому исполнителю записать результат после повторного захвата.
Одного worker достаточно; дополнительные процессы не нужны.

## Состояния и актуальность

`pending` означает ожидание или паузу перед повтором, `running` — извлечение,
`ready` — сохранённый текст, `missing` — в книге нет описания, `error` —
исчерпаны три попытки. Ошибка одного ZIP не удаляет книгу из каталога.
Повторы идут с паузой 30 и 60 секунд. При новом обращении через 24 часа
состояние `ready`, `missing` или `error` снова ставится на проверку. Пока
повторная проверка идёт, прежний сохранённый текст остаётся видимым.

Для востребованной книги worker вычисляет SHA-256 отпечаток из устройства,
inode, размера и `mtime_ns` исходного ZIP, а также CRC, размера и сжатого
размера конкретного члена ZIP. При совпадении с прежним отпечатком разбор
книги пропускается. Изменение INPX само по себе не сбрасывает аннотации;
исходный ZIP проверяется при следующей фоновой проверке востребованной книги.
Перед записью worker под блокировкой строки сверяет путь/имя/тип/доступность
книги и статистику ZIP с началом задания. Если они изменились, результат
отбрасывается и задание возвращается в очередь. Это проверка источника на
момент записи; внешние изменения файла после проверки обнаружатся при
следующем обращении и проверке.

Извлекатель работает в отдельном дочернем процессе: читает не более 16 МиБ
распакованной книги, ограничен 512 МиБ адресного пространства, 20 секундами
CPU и 30 секундами реального времени. Архив и его член закрываются через
контекстные менеджеры. Этот предел относится только к аннотации и не меняет
правила импорта INPX-книги в каталог. Реальная старая БД не предоставлена,
поэтому миграция её данных пока не проверена.

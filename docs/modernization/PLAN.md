## M00 — проверяемое исходное состояние
Подзадачи M00 (добавлены для проверки условий до запуска):
- M00.1 `done`: Git, зависимости, инструменты и локальная подготовка сверены; факты записаны в `baseline.md`.
- M00.2 `done`: dev-БД и тестовая библиотека проверены без изменений данных; результат в `baseline.md`.
- M00.3 `skipped`: legacy-запуск и исходные тесты не выполнены; пользователь разрешил продолжить без них. Результат тестов до модернизации неизвестен.
- M00.4 `done`: команды проверены на синтаксис, исключения Git и итоговый diff проверены; невыполненные команды явно обозначены в `baseline.md`.

Зафиксировать SHA, ветку, remotes, версии инструментов и состояние Git.
Определить реальные зависимости и совместимую версию Python; не устанавливать старые
requirements в целевой Python 3.13. Отдельно зафиксировать необходимые системные пакеты.
Проверить dev-БД, определить команды запуска, тестов и настройки пути тестовой библиотеки.
Требование воспроизвести старый запуск и выполнить исходные тесты отменено пользователем
для текущей модернизации; результаты не следует считать успешными или исходно упавшими.
Добавить безопасные повторяемые команды запуска и проверок, а также исключения Git.
Подробно декомпозировать ближайший этап; не расписывать заранее десятки гипотетических задач.
**Готово с ограничением:** инвентаризация и проверки окружения выполнены; legacy-запуск
и исходные тесты не выполнены по решению пользователя. Разрешено продолжить M00B–M05.

Исходные факты и пропущенные проверки записаны в `baseline.md`. Django 2.2 указан
только в `Pipfile.lock`; установленное окружение с этим Django не подтверждено.

## M00B — минимальная адаптация для запуска и тестирования
Цель: Python 3.13, Django 5.2 LTS, uv, `pyproject.toml` и `uv.lock` со стабильными
совместимыми патч-версиями. Не ставить старые requirements как есть и не обновлять
все пакеты до latest без проверки. Сохранить встроенную Constance, данные и цепочку
миграций. Менять только необходимое для установки, загрузки Django/настроек/моделей/
миграций, подключения к отдельной тестовой PostgreSQL и выполнения существующих тестов.

Подзадачи (причина — отделить разрешение зависимостей от адаптации кода и проверок):
- M00B.1 `done`: совместимые зависимости разрешены `uv lock` и установлены `uv sync` в отдельное Python 3.13 окружение.
- M00B.2 `done`: `manage.py check` прошёл с кодом 0; удалённые Django API заменены, встроенная Constance загружается.
- M00B.3 `done`: `showmigrations --plan` и `makemigrations --check --dry-run` прошли; 21 миграция применена в новой `sopds_m00b_test`, пробная запись и integer ID сохранились при повторной миграции.
- M00B.4 `done`: 40 тестов действительно выполнены; после адаптации имён assert API остались 4 документированных падения по языку книг, 0 ошибок загрузки.

**Готово:** окружение воспроизводимо; Django check проходит; исторические миграции
загружаются; тесты действительно выполняются; команды, коды выхода, ошибки и
ограничения записаны. Это не завершает M01/M02 и не подтверждает реальную миграцию.

## M02 — совместимый поддерживаемый стек
Завершить миграцию проекта на уже запущенный в M00B Python 3.13 / Django 5.2 LTS.
Согласовать исторические списки зависимостей с `pyproject.toml`/`uv.lock`, не оставлять
расходящиеся активные списки.
Решить перенос встроенной Constance и её данных, заменить устаревшие API.
Не удалять старые миграции и не менять ID/типы ключей случайным изменением defaults.
Разделить безопасные dev/prod-настройки, исключить публичный резервный SECRET_KEY.
**Готово:** проверки проходят на целевом стеке; схема и данные мигрируют в тестах.
Предоставленную копию прежней БД проверять отдельно; без неё записать ограничение.

**Готово:** тесты OPDS, авторизации и скачивания, безопасных путей и ограничений обработки.

## M05 — готовность кандидата

Реальную читалку проверяет пользователь, если агент не имеет доступа к ней.
**Готово:** подтверждённые результаты и ограничения записаны. Автоматического push,
merge, выпуска и переноса production нет. Не начинать новые улучшения ради продолжения.

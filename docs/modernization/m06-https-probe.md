# M06.5g: LAN HTTPS-проба на искусственных данных

Дата: 2026-09-25. Пользователь указал `192.168.88.44` и поручил проверить
HTTPS и реальную OPDS-читалку. Адрес назначен интерфейсу `enp1s0` этой Ubuntu.
Production, исходные книги и прежняя рабочая БД не использовались.

## Изоляция и запуск

- Из проверенного снимка M06.2 восстановлена новая одноразовая БД
  `sopds_m06_https_probe_20260925` и отдельная копия искусственной библиотеки
  `.local/https-probe/library`. Архив до распаковки проверен на ссылки и выход
  из `library/`; `migrate --check` прошёл. Только в новой БД установлен
  `SOPDS_ROOT_LIB` на эту копию.
- Caddy 2.11.4 получен как пользовательский бинарный файл в `.local/caddy-probe`,
  без системной установки. SHA-512 архива совпал с файлом контрольных сумм
  [официального релиза](https://github.com/caddyserver/caddy/releases/tag/v2.11.4).
  Первая загрузка архива оборвалась соединением, повторная прошла. Первый
  preflight снимка остановился из-за отсутствующего `python` в PATH; повтор
  с `.venv/bin/python` прошёл до создания БД.
- Непривилегированный процесс не может слушать порт 443 на этом хосте
  (`net.ipv4.ip_unprivileged_port_start=1024`). Для пробы Caddy слушает только
  `192.168.88.44:8443`, Gunicorn — только `127.0.0.1:8000`. Оба запущены как
  временные пользовательские systemd units `sopds-m06-caddy.service` и
  `sopds-m06-gunicorn.service`; статус после проверки — `active`.
- Пробный Caddyfile находится только в `.local/https-probe/`, включает
  `tls internal` и `skip_install_trust`. Внутренний CA не добавлялся в
  системное хранилище. Репозиторный шаблон для порта 443 успешно прошёл
  `caddy adapt`; пробный Caddyfile прошёл `caddy validate`.

## Проверки

- Caddy выпустил сертификат для `192.168.88.44` через локальный CA; событие
  `certificate obtained successfully` есть в журнале. `openssl s_client`
  с корневым CA и проверкой IP сообщил `Verification: OK`, TLS 1.3.
  SHA-256 fingerprint корневого CA:
  `6F:75:2F:88:08:B9:EE:7A:0E:57:20:C2:AC:D6:7C:34:87:EE:E1:1C:D6:9A:4B:A3:B7:51:E5:29:97:AF:AC:0B`.
- С клиентом, явно доверяющим этому CA, без `-k` или исключений TLS:
  web, web-поиск, OPDS, OPDS-поиск и static дали HTTP 200; скачивание
  `M06 Restore Probe` дало HTTP 200 и точные байты файла из копии библиотеки.
  OPDS-ответ имеет тип `application/atom+xml`. Заголовка HSTS нет.
- `manage.py check --deploy` с private-настройками и этим IP завершился с
  единственным ожидаемым `security.W004`; `collectstatic` и
  `gunicorn --check-config` прошли. Тестовая книга имеет готовую аннотацию
  `Saved synthetic annotation`.

Проверки сделаны с этого же Ubuntu-хоста по его LAN-IP. Доступ из другого
устройства, доверие CA в конкретной читалке и её поведение ещё не проверены;
это остаётся M06.4/M06.5d. Порт 443 и системный сервис Caddy не проверялись.

Тестовый адрес: `https://192.168.88.44:8443/opds/`. Публичный корневой
сертификат для переноса на устройство:
`.local/https-probe/data/caddy/pki/authorities/local/root.crt`.
Приватные ключи CA остаются только в `.local/https-probe/data/` и не должны
передаваться на устройство или попадать в Git. Временные сервисы можно
остановить командами `systemctl --user stop sopds-m06-caddy.service` и
`systemctl --user stop sopds-m06-gunicorn.service` после проверки читалки.

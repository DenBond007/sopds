# M06.11 — запросы полки и настроек web

Дата: 2026-09-25. Выполнен следующий небольшой шаг M06.10 по поручению
пользователя: убрать отдельную загрузку книг боковой полки и повторное
чтение настроек внутри циклов web-страниц.

## Изменения

- Полка загружает связанные книги через `select_related('book')` и читает
  `row.book`. Лимит восемь, порядок `-readtime, pk`, ID, время чтения,
  заголовки, ссылки и фильтрация по текущему пользователю сохраняются.
- Поиск книг и каталог читают `SOPDS_AUTH` перед обработкой списка и
  используют локальное значение для элементов. Контекст страницы повторно
  использует уже прочитанные флаги авторизации и алфавитного меню.
- Значения живут только в текущем вызове обработчика/контекстного процессора;
  глобальный или межзапросный кеш не добавлен. Проверка входа продолжает
  самостоятельно читать настройку при каждом новом HTTP-запросе.
- Схема БД, Constance backend, OPDS и конфигурация служб не менялись.
  Остальные рекомендации M06.10 этим шагом не реализовывались.

## Измерения до/после

Замеры сделаны через `CaptureQueriesContext` для настоящих ответов Django
test client. Использованы искусственные записи и PostgreSQL 17; начальная
инициализация отсутствующих настроек Constance выполнена перед замером.
Время ответа под нагрузкой и дополнительные HTTP-запросы браузера за
обложками не измерялись.

| Сценарий | До | После |
|---|---:|---:|
| SELECT полки/книг: полка пуста | 1 | 1 |
| SELECT полки/книг: одна книга | 2 | 1 |
| SELECT полки/книг: восемь книг | 9 | 1 |
| SELECT настроек: поиск, одна книга | 13 | 11 |
| SELECT настроек: поиск, 60 книг | 72 | 11 |
| SELECT настроек: каталог, одна книга | 12 | 10 |
| SELECT настроек: каталог, 60 книг | 71 | 10 |
| Всего SQL: поиск 60 книг, вход выполнен, полка пуста | 85 | 24 |
| Всего SQL: каталог 60 книг, вход выполнен, полка пуста | 83 | 22 |

Постоянное число SELECT настроек подтверждено при включённой и выключенной
авторизации. Проверка следующего запроса подтвердила изменение размера
страницы, алфавитного меню и флага конвертации. Включение авторизации
закрывает доступ анонимному пользователю, выключение вновь открывает его.
В полке остаются прежние записи текущего пользователя, чужие не выдаются;
после HTTP-запроса ID, книги и readtime в БД совпадают с исходными значениями.
